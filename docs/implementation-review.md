# Implementation and performance review

The module presents service topology, status, current SLA reporting metrics and service problems. The table and graph share branch expansion state. The graph is now collapsed on each page visit and is fetched and rendered only after opening it.

## Findings addressed

| Priority | Original behavior and impact | Implemented change |
| --- | --- | --- |
| High | The page controller loaded service data, but the view discarded it and immediately requested the same data through AJAX. Cookie restoration could add another page load. | The page controller now prepares filters only. Cookie selections are restored before the first data request without submitting the page again. |
| High | Collapsed branches still generated every descendant row, hiding them with CSS. Large or shared subtrees inflated HTML and browser work. | Only expanded, reachable rows are constructed. Shared descendants are rendered once. Visibility and path traversal have visited-node guards. |
| High | Service names were fetched for the entire hierarchy even when most descendants were collapsed. | The global scan returns only IDs, status and parent IDs; names are requested in batches for displayed rows and their breadcrumb ancestors. |
| High | Every refresh serialized the full graph and built its SVG even when the panel was hidden. | Graph data is generated only for an open panel and contains only displayed services and edges. Closing destroys SVG nodes, timers, listeners and root-cause requests. |
| High | SLA sorting widened the shared visible-ID list to every service, also widening root-cause queries. | Only visible siblings receive sort values. Hidden branches are sorted when opened. Root-cause scope is independently restricted to visible problem rows. |
| High | SLI responses were indexed as service/period instead of period/service. Multiple services could receive another service's metrics or no metrics. | Read the latest returned period, then index by the returned service-ID order. The API does not promise request order. See [Zabbix sla.getsli](https://www.zabbix.com/documentation/7.0/en/manual/api/reference/sla/getsli). |
| High | SLA-only filtering calculated SLI for the complete candidate hierarchy. SLA Name and SLO also triggered timeline calculations. | Resolve enabled-SLA membership through service configuration, reuse it within the request, and calculate SLI only where metric columns, sorting or displayed graph nodes require it. |
| High | Root causes were inferred from problem tags, omitting inherited problems and ignoring service tag operators. One broad problem query was made per tag group. | Batch native `selectProblemEvents` for the requested services and resolve event links in batches with ordinary event permissions. See [Zabbix service.get](https://www.zabbix.com/documentation/7.0/en/manual/api/reference/service/get). |
| Medium | Graph root causes stayed cached across data refreshes, pending requests could be duplicated, and failures became empty results. | Cache within the current graph, deduplicate pending requests and expose a retry after failure. Destroying a graph prevents stale callbacks from changing it. |
| Medium | Concurrent refreshes could apply an older response after a newer one. | Cancel superseded requests and accept callbacks only from the current request. |
| Medium | Array parameters generated by PHP were not parsed as arrays by JavaScript Curl. Unchecking every column omitted the parameter and restored all default columns. | Pass normalized filter values as JSON, send an explicit empty-column marker and whitelist column/status input. Column changes fetch newly required details. |
| Medium | Controllers checked the Hosts permission instead of Services. Module initialization replaced the entire shared filter namespace registry. | Use the Services permission for the menu and endpoints, and add only this module's namespace. |
| Medium | Uptime had no numeric sort value, SLA numeric strings were compared as names, undefined SLI could show a negative percentage, and multiple-SLA selection depended on API order. | Keep numeric duration values, compare metrics numerically, show undefined SLI as missing, and select enabled SLAs deterministically by name/ID. Missing sort values remain last in both directions. |
| Medium | Empty graph focus fell back to showing all services; the 500-node limit was bypassed by focus and checked after layout. | Preserve empty results, combine search and problem focus, and enforce the limit before layout in every mode. Focus traversal uses queues instead of repeated recursive walks. |
| Low | CSV headers depended on translated text, controls reused IDs, the refresh timestamp did not update, malformed cookies could break initialization, and translations were embedded into JavaScript without string escaping. | Use stable CSV keys, unique control IDs, update the timestamp on success, tolerate malformed cookie values and JSON-encode translated strings. |

## Loading behavior

1. The page prepares filters and a loading container without querying services or SLA metrics.
2. AJAX fetches service IDs, statuses and parent IDs, applies filters and restores ancestors in batches.
3. Expansion state determines displayed service IDs. Names are fetched for those rows and breadcrumb ancestors; SLA calculations and table root causes are restricted to displayed rows.
4. The response contains table rows for displayed services. A closed graph has no graph dataset and no SVG nodes.
5. Opening the graph requests its displayed nodes and their SLA labels. Selecting a problem node fetches root causes if the table did not already load them.

Sorting and filter links retain the current filters and expansions. Graph visibility remains open across table refreshes but resets to collapsed on page navigation. Graph focus searches displayed branches; the page's service-name filter searches the hierarchy.

## Remaining costs and tradeoffs

- This is lazy detail loading, not complete elimination of hierarchy reads. Global status counts, status filters, ancestor retention and Expand all still require service IDs, statuses and parent relationships. Name matching happens inside the API; hidden descendant names are not returned. A future root/child endpoint with server-side paging would reduce topology reads further, but global totals and filters would need separate query paths.
- SLA-only filtering must discover membership for hidden matching services to retain their ancestors. It no longer calculates their SLI. Membership is batched per SLA; installations with many enabled SLAs can still incur many configuration queries.
- Native service problem resolution follows Zabbix's status propagation. The inspected Zabbix 7.0 implementation internally scans service relationships and status data even for restricted service IDs. This module batches that operation once per request; it cannot make the upstream implementation lazy. Hiding the Root cause column defers it until graph selection.
- A displayed service with many root causes still retrieves its full list for hints, export and the graph's Show more control. That control expands an already loaded list; it is not server pagination.
- Expand all remains an explicit request to display the full tree. The table has no row pagination or viewport virtualization. The graph stops at 500 matching nodes before layout; use filters to reduce a large selection.
- A shared service appears under the first expanded branch that reaches it in the sorted table. The graph retains multiple visible-parent edges. Breadcrumbs and service links use its first accessible parent path.
- The existing one-hour automatic refresh interval is unchanged. This review does not establish production latency or database-load benchmarks.

## Validation

- PHP syntax validation for module files in the available Zabbix container.
- Standalone backend tests on PHP 8.2 and 8.3: no initial API fetch, visible-only enrichment and sorting, reversed service order in SLI responses, undefined SLI, inherited problems, SLA-only filtering without SLI, empty columns, ancestor restoration and shared descendants.
- A synthetic 10,000-hidden-service test verifies one topology query, one name batch for the single visible root, and no SLA/root-cause calls when optional columns and the graph are closed. Its graph dataset contains one root node.
- Dependency-free JavaScript tests execute the module's actual view code against a small DOM model, covering graph open/close, superseded responses, expansion state, empty focus and root-cause request deduplication/retry.
- Real Zabbix HTML classes render the partial with fixtures, using both the available frontend and the local Zabbix 7.0 source: collapsed output omits descendant rows, SVG markup and graph data, opening adds the visible graph dataset, service names remain escaped and control IDs are unique.
- No connected browser was available for interactive visual testing. Live authenticated API behavior, role combinations and production performance still require validation on the target Zabbix installation.
